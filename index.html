主要项目案例

1｜虚拟制片产线：把 AI 边界、报价与修改决策做成同一套产品

英雄电竞 · 内容矩阵技术中台
问题

报价靠人工逐单估算，脚本参考很难对齐，关键信息常常做到一半才补齐；修改反复来回，却看不清客户已经改了几轮、还该不该继续改。

产品判断
  • 对外：标准报价单 + 项目信息表，锁定时长、制作方式（UE / 离线）、是否实拍、交片尺寸、帧率、秒数、是否解算、截止日期、预算、修改次数、A Copy / B Copy 审核节点等字段，统一环节单价与人天公式。重点项目的让利走线下评估的例外流程，而非一单一价。
  • 对客户：每次反馈与制作进度写进同一条记录，让客户看见「又改回了上一版」，必须做出取舍，而不是无限修改。
  • 对内：在飞书铺开工作流 / 审核流 / 制作流与甘特排期，记录预估人天、实际人天、反馈人天用于复盘。
  • AI 边界：允许用于剧本草稿、脚本参考、分镜与场景氛围、角色三视图，用来对齐描述与反馈；确认方向后，原画优化与模型必须人手完成，保证后续环节拿到真实资产。最终交付给客户的成片输出不使用 AI。
  • 验收：内部先审，制片链路与技术负责人共审后再交客户。未通过时先判断是提示词不足还是资产问题，再决定小改或重做。
结果

兼顾双部门支援技术中台的约半年内，经手实际入账约 120 万元（3-4 个项目），平均利润率 45%-50%。引入 AI 的创意前期环节沿用当时内部口径：制作提效 30%+、人天成本下降 20%+；该口径仅指剧本草稿、脚本参考、分镜氛围、角色三视图，人天基线来自飞书上各环节预估 / 实际 / 反馈人天的复盘。

2｜企业内部 RAG：能引用才答，答不上转人工

叠境数字 · 面向全体员工的制度问答
问题

入职培训之后，和自己当下无关的制度没人记得，员工往往到真正需要时才去问 HR。答案手册里都有，但检索和确认的成本全部压在 HRBP 身上。

技术形态

向量检索 + 大模型作答的 RAG 结构。员工手册十几页，拆成 200-300 条问答对入向量库，用户提问后语义召回相近条目，模型基于召回内容作答。因涉及员工制度与 HR 敏感信息，数据不出内网：采用私有化部署的开源模型（Ollama + LLaMA 系），不调用外部 API。

产品判断
  • 切片口径：手册按问答对切分，而不是按字数硬切，召回质量更可控。
  • 答与不答的边界：能引用手册才答，不许编；薪酬敏感信息不入库；纠纷类问题直接转 HRBP。
  • 兜底策略：检索不到就明确说明当前无法回答，并指向员工手册中大致可查的位置。
  • 评测机制：以 100 题为一集，扩写不同问法打向量库，由我定评分口径、HRBP 按维度打 0/1，本轮迭代评了 3-4 轮。
  • 回归机制：制度更新后先测受影响部分，最后再跑一次全量评测，避免只顾新条目、旧条目回退。
结果

员工问到的是 HRBP 确认过的口径，减少「培训完又来问一遍」的重复咨询。输出始终可追溯到手册来源，不产生无依据的回答。

3｜VTKD / VTKD2：识别不稳时先保证能玩，再让卡点可见

英雄电竞 · Pico 4 / Quest
问题

从新加坡开发侧接手后，上海人手少；识别不准时模型会错乱，活动要跑一整天，实验室测不全那种替换强度。角色制作则容易一拖再拖：期望一个半月完成，原画越改越多，并行节点看不见，到期交不出，但没人能提前说出卡在哪一环。

产品判断
  • 硬件路径：对比惯性动捕、摄像头动捕、光学动捕棚。摄像头场地要求高、精度达不到对战；光学棚单次移动及搭建约数万元级，不适合巡展。结论是小成本继续打磨 AXIS。
  • 上场策略：内测识别 bug 多，用「当前最小 bug 包」去活动，不等识别完美。我在上海做版本冻结、应急和资源保障，通常派测试 + 程序去现场。
  • 版本筛减：人手紧张的第一年约 6 个可玩版本由我带头推进；VTKD 新增 10 个游戏角色、3 个落地场景。VTKD2 起主控可行性、版本内容与需求筛减，明显完不成的在前中期砍掉。
  • 工作流结构：观察团队真实制作方式后，落地四级结构：版本规划 → 业务线 → 需求 → 任务。每个环节由执行方自估工期，超期自动提醒。业务线分美术与策划两条，美术下再分角色与场景。
  • 需求流转：策划内部评审 → 写入当版本 → 三方会对齐 → 程序制作 → 策划验收 → 测试验收 → 待回归 → 灰度 → 合入可玩版本。外包质量早期由我直接审核，后期转为质量监控，由主美统一对外包给出质量意见。
结果

完成巴黎奥运会电竞周展示、新加坡乌节路快闪。工作流覆盖研发组约 30 人，每周流转约 10-15 条需求与约 20 条缺陷，外部支持 3-4 家外包。

4｜数字人口型 V3 → V4：先定采集与验收，再对客户承诺

叠境数字 · 第一财经数字主播伊可
问题

3D 口型与 2D 不同：2D 只需嘴部张合，3D 的 a / e / i / o / u 必须在模型上做足。当时线上版本口型幅度不够，客户也反馈不够准，但在改进方案验证之前，不能对外承诺「可以优化」。

产品判断
  • 与算法同学讨论后确定 landmark → 3D 人脸关键点的方案方向，并定义数据集规格与验收标准。
  • 带队完成采集：到电视台选拔真实主播，面部捕捉后筛选各口型表现最佳的采集人，再筛选新闻文稿，完成 3 天约 20 小时的采集。
  • 用对比测试回答核心产品问题——是堆更多数据更好，还是只保留特定主播更好；未达标则回头优化数据集，而不是直接换模型。
  • 组织算法专家 QC，查看训练指标与对比测试结果，口型观感达到验收标准才放行，不以「算法说改好了」为准。
结果

V3 → V4 的观感提升明显超过前三个版本的累计幅度，与直接采集效果相似度 80% 以上，客户各部门反馈真实性提升、几乎无返工。该版本为全站升级，第一财经虚拟主播项目直接升级至最新版本，AIGC 数字人平台整体同步，约 3-4 组客户受益。
